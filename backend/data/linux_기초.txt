Linux와 서버의 역할
Linux는 서버와 개발 환경에서 널리 사용하는 운영체제입니다. 사용자는 터미널에서 명령어를 입력해 파일을 살펴보고 프로그램을 실행하며 오류를 확인할 수 있습니다. 웹 서비스가 작동하지 않을 때 화면만 보는 것으로는 원인을 알기 어렵습니다. 서버의 파일, 실행 중인 프로세스, 로그를 차례로 확인하면 문제를 좁힐 수 있습니다. 이 문서는 수업에서 자주 마주치는 기본 명령을 간단한 사례와 함께 정리합니다.

현재 위치와 파일 확인
터미널에서 pwd는 현재 작업 중인 폴더의 경로를 보여줍니다. ls는 해당 폴더의 파일과 하위 폴더를 나열합니다. ls -l을 사용하면 파일의 소유자, 크기, 수정 시각, 권한 등도 확인할 수 있습니다. cd data처럼 cd 뒤에 폴더 이름을 쓰면 그 폴더로 이동합니다. 상대 경로는 현재 위치를 기준으로 해석되므로 명령이 예상과 다르게 동작하면 먼저 pwd를 확인하는 습관이 유용합니다.

텍스트 파일 읽기
cat 파일명은 텍스트 파일 전체를 터미널에 보여줍니다. 파일이 길면 less 파일명으로 한 화면씩 읽을 수 있습니다. head 파일명은 앞부분을, tail 파일명은 뒷부분을 확인할 때 사용합니다. grep '오류' 파일명은 파일에서 특정 단어가 포함된 줄을 찾습니다. 한글이 깨져 보이면 파일의 인코딩과 터미널의 문자 표시 설정을 확인해야 합니다. 이 수업의 자료 파일은 UTF-8로 저장합니다.

파일 권한의 기본
Linux는 파일에 대해 읽기(r), 쓰기(w), 실행(x) 권한을 구분합니다. 권한은 소유자, 그룹, 그 밖의 사용자에게 따로 적용됩니다. ls -l의 출력 앞부분에서 이 정보를 확인할 수 있습니다. 예를 들어 파일을 읽을 수 없다는 오류가 나오면 파일이 존재하는지뿐 아니라 현재 사용자에게 읽기 권한이 있는지도 확인해야 합니다. 권한을 넓히기 전에 어떤 사용자에게 실제로 접근이 필요한지 먼저 판단합니다.

chmod로 권한 변경
chmod 명령은 파일이나 폴더의 권한을 변경합니다. 예를 들어 chmod u+x run.sh는 소유자에게 실행 권한을 추가합니다. chmod 644 memo.txt는 소유자에게 읽기와 쓰기, 다른 사용자에게 읽기 권한을 부여하는 예입니다. 숫자 방식에서 읽기는 4, 쓰기는 2, 실행은 1이며 각 사용자 범주에서 값을 더합니다. 실습에서는 권한 변경 전후에 ls -l을 실행해 실제로 무엇이 바뀌었는지 확인합니다. 모든 사용자에게 쓰기 권한을 주는 식의 과도한 설정은 피합니다.

프로세스와 실행 중인 프로그램
프로세스는 실행 중인 프로그램입니다. ps 명령으로 프로세스 목록을 볼 수 있고 ps aux로 더 많은 정보를 확인할 수 있습니다. 한 프로그램이 시작되지 않거나 이미 사용 중인 포트를 차지할 때는 프로세스가 실제로 떠 있는지 확인해야 합니다. 개발 중에는 웹 서버를 켠 터미널을 그대로 두고 다른 터미널에서 테스트하는 경우가 많습니다. 무작정 프로세스를 종료하기보다 어떤 프로그램인지 확인한 후 조치합니다.

서비스 상태 확인
Ubuntu 서버에서 systemd로 관리하는 서비스는 systemctl status 서비스명으로 상태를 확인할 수 있습니다. 서비스가 동작하지 않으면 단순히 다시 시작하기보다 상태 메시지와 로그를 먼저 읽는 것이 좋습니다. 서비스를 다시 시작해야 한다면 권한이 필요한 경우가 있으므로 sudo 사용 여부를 확인합니다. sudo는 관리자 권한으로 명령을 실행하므로 명령의 효과를 이해한 다음 사용해야 합니다.

로그로 오류 추적
로그는 프로그램이 언제 어떤 일을 했고 어떤 오류가 났는지 기록합니다. journalctl -u 서비스명은 해당 서비스의 기록을 확인하는 데 사용합니다. journalctl -f는 새로 기록되는 로그를 계속 보여줍니다. 오류를 조사할 때는 오류 문장 한 줄만 떼어 보지 말고 발생 시각과 앞뒤 메시지도 함께 살펴봅니다. Python 웹 서버를 로컬에서 실행할 때는 터미널에 출력된 traceback이 실패 위치를 알려주는 경우가 많습니다.

업데이트와 패키지
Ubuntu의 apt는 프로그램 패키지를 설치하고 업데이트하는 도구입니다. sudo apt update는 설치 가능한 패키지 목록을 새로 확인하고, sudo apt install 패키지명은 지정한 패키지를 설치합니다. 목록을 확인하는 명령과 실제 프로그램을 설치하거나 바꾸는 명령은 역할이 다릅니다. 수업용 PC에서는 관리자 권한과 네트워크 정책에 따라 설치가 제한될 수 있으므로 먼저 현재 설치 상태를 확인합니다.

LLM 웹 서비스와 연결해서 생각하기
챗봇 화면은 잘 열리는데 답변이 오지 않는다면 화면, API 서버, 외부 모델 호출 중 어디에서 멈췄는지 나누어 확인합니다. 로컬에서는 Python 서버 터미널의 오류를 보고, 배포 후에는 플랫폼의 함수 로그를 확인합니다. 자료 파일을 읽지 못하면 경로와 권한을 확인하고, API 키를 찾지 못하면 서버 환경변수 설정을 확인합니다. 비밀 키를 코드나 공개 저장소에 적지 않는 것은 Linux 명령을 잘 아는 것만큼 중요한 운영 습관입니다.
